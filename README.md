# IT Support Operations Dashboard

A full-featured internal IT support management system built with **Next.js 14 (App Router)**, **Supabase**, and **Tailwind CSS (shadcn/ui)**. Supports multiple branches, role-based access control, a public ticket submission portal, inventory tracking, Excel import/export, and an analytics dashboard.

Live demo: https://itsupportamreicanafoods.netlify.app

## Features

### Dashboard
- KPI cards: Open Tickets, Low Stock, Delayed Suppliers, Pending Requests, Devices in Maintenance, Parts Installed Today
- 6 analytics charts: Tickets per month, Inventory status, Most common issues, Parts consumption, Device maintenance stats, Recent activity feed
- Drag-to-reorder and resize KPI cards and chart sections (persisted in `localStorage`)
- Demo mode (zeroed data + banner) when Supabase is not connected

### Tickets
- Internal ticket management with status workflow: `open → in_progress → waiting_user → resolved → closed`
- Priorities: `low / medium / high / urgent`
- Per-ticket detail page with asset linkage
- Excel import with template download
- Public ticket portal at `/support` (no login required)
- Auto-generated sequential ticket numbers: `TCK-YYYY-NNNN`
- Optional file attachment (screenshot upload to Supabase Storage)
- n8n webhook trigger on new public ticket (optional)

### Assets
- Full asset lifecycle management (active, in_maintenance, retired, lost, spare)
- Per-asset tabbed profile: Overview, Maintenance History, Installed Parts, Linked Tickets, Attachments
- Search by tag, serial number, or assigned user
- Excel import

### Spare Parts & Inventory
- Spare parts catalog with stock tracking
- Low stock alerts (when `current_stock ≤ reorder_level`)
- Consumable flag per part
- Atomic stock operations: **Use part on asset** (OUT transaction + stock decrement + history entry) and **Undo use** (fully reversed in one operation)
- Inventory log with filter by part
- Spare part ↔ asset compatibility linking

### Purchase Requests
- Status workflow: `draft → submitted → ordered → waiting_supplier → delivered → cancelled`
- Per-request detail view
- Excel import
- Delayed supplier tracking (used in KPI dashboard)

### Suppliers
- Supplier directory with SLA tracking
- Linked purchase requests and follow-up notes
- Excel import

### Notifications
- In-app notification center with unread badge on bell icon
- Notifications generated by n8n automations or created directly via the service
- Mark individual or all as read

### Reports
- 12-month analytics for all modules
- Excel export for: Tickets, Assets, Spare Parts, Inventory, Purchase Requests, Suppliers

### Settings
- Theme toggle (Light / Dark / System)
- Language toggle (English / Arabic with RTL layout)
- Admin-only: manage dropdown lists (device types, brands, departments, spare part categories, support form options)

### Accessibility & UX
- Skip-to-main-content link
- aria-labels on all icon-only buttons
- Full keyboard navigation via ⌘K / Ctrl+K command palette
- Collapsible sidebar with hover tooltips in icon-only mode
- Responsive design (mobile drawer sidebar)
- SkeletonRow loading states in all tables
- EmptyState components with contextual messages and actions
- Dismissible viewer-mode banner (persisted per session)
- ConfirmDialog for all delete/undo operations (replaces browser `confirm()`)
- Toast notifications via Sonner for all mutations

## Database Setup

### 1. Create Supabase Project

Go to [supabase.com](https://supabase.com), create a new project, and note your **Project URL** and **anon key** from **Project Settings → API**.

### 2. Run the Base Schema

In **Supabase → SQL Editor**, run the full contents of:

```
database/schema.sql
```

### 3. Run All Migrations (in order)

Run each of the following in the SQL Editor:

| # | File | What it adds |
|---|---|---|
| 1 | `database/migrations/add-multi-branch.sql` | `branches` table + `branch_id` columns |
| 2 | `database/migrations/add-lookup-options.sql` | `lookup_options` table |
| 3 | `database/migrations/add-support-form-lookup-options.sql` | Seeds default dropdown options |
| 4 | `database/migrations/add-spare-part-assets.sql` | `spare_part_assets` join table |
| 5 | `database/migrations/add-spare-part-consumable.sql` | `is_consumable` on spare_parts |
| 6 | `database/migrations/add-ticket-attachment.sql` | `attachment_url` on tickets |
| 7 | `database/migrations/add-asset-profile.sql` | `asset_id` on tickets + `asset_attachments` table |
| 8 | `database/migrations/add-admin-delete-all.sql` | Admin delete RLS policy |
| 9 | `database/rls-allow-anon.sql` | Anonymous insert on tickets (for public form) |

> **All migrations use `IF NOT EXISTS` / `IF NOT EXISTS` — safe to run multiple times.**

### 4. Set User Roles

Use the helper scripts to set up your admin and support users:

- `database/migrations/set-admin-and-support-users.sql`
- `database/migrations/assign-support-user-branch.sql`

### 5. Create Storage Bucket (optional, for ticket attachments)

In Supabase **Storage**, create a bucket named `ticket-attachments`. Add a policy allowing the service role to upload files. This is only needed if you want file attachments on the public support form.

## Environment Variables

Create a `.env.local` file in the project root (copy from `.env.example`):

```env
# Required
NEXT_PUBLIC_SUPABASE_URL=https://your-project-ref.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key-here

# Optional
REQUIRE_AUTH=true                          # Set to "false" to disable auth redirect
N8N_NEW_TICKET_WEBHOOK_URL=https://...     # n8n webhook URL for new ticket notifications
```

> **Note:** If `NEXT_PUBLIC_SUPABASE_URL` is not set, the app runs in demo mode (all data calls fail gracefully, dashboard shows zeroed KPIs).

## Roles & Permissions

Three roles are assigned in the `profiles` table (`role` column):

| Role | Login Required | Can Read | Can Create/Edit/Delete | Can Change Settings | Notes |
|---|---|---|---|---|---|
| `admin` | Yes | All branches | Yes | Yes (dropdown lists, user roles) | Sees all branches; can filter by branch |
| `support` | Yes | Own branch | Yes | No | Locked to their assigned branch |
| `viewer` | Yes | Own branch | No | No | Read-only; dismissible banner shown |

`isAdmin` and `canEdit` are provided by `BranchProvider` and checked throughout the app.

### Assigning Roles

Find the user's UUID in **Supabase → Authentication → Users**, then run:

```sql
-- Make a user admin
UPDATE public.profiles SET role = 'admin' WHERE id = 'user-uuid-here';

-- Assign support user to a branch
UPDATE public.profiles
SET role = 'support', branch_id = (SELECT id FROM branches WHERE code = 'BRANCH_CODE')
WHERE id = 'user-uuid-here';
```

## Multi-Branch Support

- All data tables have a `branch_id` column.
- **Admins** can switch the active branch filter from the sidebar footer. Selecting "All Branches" (null) shows company-wide data.
- **Support/Viewer** users are assigned a `branch_id` in `profiles` and only see data for that branch.
- All service queries accept an optional `branchId` parameter and filter accordingly.

## Public Support Portal

The `/support` route is publicly accessible (no login required).

**Features:**
- Submits a ticket directly to the `tickets` table
- Branch selection from available branches
- Department, issue type, and priority populated from `lookup_options` (configurable by admins in Settings → Lists)
- Optional screenshot upload (JPEG, PNG, GIF, WebP; max 5 MB → Supabase Storage `ticket-attachments` bucket)
- Rate limited: max 2 tickets per email per 5 minutes
- Sequential ticket numbers: `TCK-YYYY-NNNN`
- Success banner shown above the form; "Submit another" resets the form
- Optional n8n webhook call on every submission (`N8N_NEW_TICKET_WEBHOOK_URL`)

## Excel Import/Export

### Import (per module)
Every major list page has an **Import from Excel** button. Flow:
1. Download the template (auto-generated `.xlsx` with correct headers)
2. Fill in rows; upload the file
3. Preview shows the parsed rows
4. Import runs row-by-row; errors are reported per-row (failed rows don't block successful ones)

Supported modules: **Tickets**, **Assets**, **Spare Parts**, **Suppliers**, **Purchase Requests**

### Export (Reports page)
The `/reports` page has an **Export** button per module that downloads a full `.xlsx` of the current data.

## Key Architectural Decisions

### No service files changed for redesign
All Supabase queries, RLS policies, and route structure are separate from the UI layer. The redesign only touched `app/globals.css`, `tailwind.config.ts`, layout components, and page UI.

### Atomic inventory operations
`useSparePartOnAsset()` in `services/stock-transactions.ts` performs three operations in sequence:
1. Creates an OUT stock transaction
2. Decrements `current_stock` on the spare part
3. Creates an asset_history entry

`reverseUseSparePartOnAsset()` fully undoes all three.

### CSS custom properties for theming
All colors are defined as CSS HSL variables in `app/globals.css`. The Tailwind config maps these to utility classes. Dark mode switches the variable values under the `.dark` class — no JavaScript class duplication required.

### Sidebar state
Collapse state is stored in `localStorage` (`"sidebar-collapsed"`). The sidebar fires a custom `"sidebar-toggle"` event so `DashboardLayout` can adjust the main content padding without a prop chain.

### Demo mode
When Supabase env vars are missing or the first DB call times out after 8 seconds, the dashboard shows zeroed KPIs with a "Demo mode" warning banner. The app remains fully navigable.

## Troubleshooting

### `ERR_NAME_NOT_RESOLVED` on login
The Supabase project URL cannot be resolved by DNS. Possible causes:
1. **Supabase project is paused** (free tier) → Go to [Supabase Dashboard](https://supabase.com/dashboard), restore the project.
2. **Wrong URL in env** → Check `NEXT_PUBLIC_SUPABASE_URL` matches the URL in Supabase → Project Settings → API.
3. **Network/VPN issue** → Try another network or disable VPN.

### `Could not find the 'attachment_url' column of 'tickets'`
The migration for ticket attachments hasn't been run. Execute in Supabase SQL Editor:
```sql
ALTER TABLE public.tickets ADD COLUMN IF NOT EXISTS attachment_url TEXT;
```

### `new row violates check constraint "tickets_priority_check"`
The `priority` column only accepts lowercase values: `low`, `medium`, `high`, `urgent`.
The app normalizes priority to lowercase before insert. If you see this error on an older deploy, redeploy the latest code from `main`.

### `403 Forbidden` on `git push`
Your Git credentials don't have push access in this shell environment. Push from your own machine or use VS Code's Source Control panel. See the [GitHub docs on personal access tokens](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens) if credentials are needed.

### Supabase schema cache error
After running migrations, Supabase may need a schema cache refresh:
- In Supabase Dashboard → **API** → click **Reload schema** (or wait ~60 seconds).
- Alternatively, restart the Next.js server.

### Empty dashboard (all zeros, no error)
- Check that `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` are set in `.env.local`.
- Verify the `profiles` row exists for your user with the correct `role` and `branch_id`.
- Check the browser console for network errors.
